# Motion MCP

Motion MCP is an AI-native, codebase-aware motion generator for Codex, Claude Code, Cursor, and any MCP-compatible coding agent.

It scans an existing app, indexes components and assets, researches the app flow, creates Rive-like page state-machine experience specs, proposes the highest-leverage motion moments, decides whether each asset belongs in a simple or premium SVG lane, generates framework-native animation code, stages the result as a reviewable diff, and applies it only after approval.

QuiverAI is the premium structured SVG provider. Motion MCP keeps the Quiver API key server-side, charges Motion credits to users, stages generated SVGs as diffs, and then animates those SVGs with host-code state machines. Simple icons, badges, loaders, decorative marks, and quick Lottie-like SVGs can be generated by the host coding model, then ingested and indexed by Motion MCP.

## What It Builds

- React / Next.js: Framer Motion, GSAP-ready SVG choreography, CSS fallback.
- Expo / React Native: Reanimated 3 + react-native-svg patterns.
- Flutter beta: AnimationController wrappers and CustomPainter/Rive-ready extension points.
- Unity beta: UI pointer interaction behavior, DOTween-ready extension points.

The product rule is simple: work with the existing codebase first. No rewrites. No invented runtime. No random generated app replacing the real one.

## V2 Motion Model

- Auto research writes `.motion-mcp/auto-research.json` with source-backed findings, ranked implementation opportunities, and context packs for Codex/Claude.
- App research writes `.motion-mcp/app-context.json` and `.motion-mcp/motion-map.json`.
- State-machine research writes `.motion-mcp/state-machine-experience.json` with one spec per detected page/screen.
- The state-machine experience spec models Rive-like layers, entry/exit/any/single/blend states, transition timing, conditions, actions, listeners, and ViewModel bindings.
- The motion map ranks top moments by brand memory, user confidence, reward, affordance clarity, perceived speed, delight, and conversion impact.
- Simple lane: `generate_simple_svg_asset` returns a strict SVG prompt/checklist for the current host coding model, then `ingest_svg_asset` validates and stages the SVG.
- Premium lane: `generate_premium_svg_asset` uses QuiverAI when asset complexity or brand importance justifies the credits.
- Rive-like contracts live in code: named states, transitions, triggers, and ViewModel-style bindings such as `isLoading`, `progress`, `count`, `isSelected`, `hasError`, `themeColor`, `avatarImage`, and `rewardLevel`.

## Local Development

```bash
pnpm install
pnpm build
pnpm dev:mcp
```

During local development, credits are stored in `.motion-mcp/credits.json` with a default local grant.

QuiverAI runs in deterministic mock mode unless `QUIVERAI_API_KEY` or `QUIVERAI_API_KEYS` is set. Set `MOTION_MCP_QUIVER_MOCK=1` to force mock mode.

### API key rotation and resilience

- `QUIVERAI_API_KEYS` accepts a comma-separated list of QuiverAI keys. The provider round-robins across them, rotating away from any key that returns 401 (auth), 402 (insufficient credits), or 429 (rate limit).
- 429 and 5xx responses are retried with exponential backoff (capped at 8s). When the response carries `x-ratelimit-reset`, that deadline is honored instead.
- Fallback model pricing matches live QuiverAI pricing: `arrow-1.1` = 20 credits, `arrow-1.1-max` = 25 credits.

### Batch generation and rig analysis

- `generate_asset_batch` takes a manifest of up to 64 items (`id`, `brief`, `lane: "premium" | "simple"`, optional `model`, `stylePreset`, `placement`). With `dryRun: true` it returns a zero-cost per-item estimate; without it, premium items are generated through QuiverAI and simple items return host-agent briefs. One failing item never aborts the batch.
- Premium generation accepts style presets: `kids-storybook`, `soft-toy`, `flat-sticker`, and `manipulative`.
- Every generated or ingested SVG now ships with a `rigReport`: which character/object roles (`eyes`, `head/body`, `mouth/beak`, `limb/wing`, `tail/tuft`, `shadow`, `sparkle`) were detected by id/data-name, what each can bind to (eye-follow, blink, press-depress, greeting lift...), and which roles are missing. Use it to verify an asset is state-machine-ready before generating animation code.

Production billing defaults:

- Free: 100 Motion credits/month.
- Pro: $20/month for 2,000 Motion credits.
- Team: $50/seat/month for 5,000 Motion credits/seat.

- Quiver-backed calls reserve `ceil(quiver_pricing_credits * 2)` Motion credits, then commit only after a usable SVG is staged.

## 3D Exercise Stack

- `@motion-mcp/anatomy-engine` - Species-aware SVG anatomy: detects parts by name or geometry, matches them to species schemas (`human-biped`, `avian-crow`), and resolves semantic actions into per-anatomy animation queues. A crow "waves" with wing lift + head bob; a human waves with arms.
- `@motion-mcp/motion-runtime` - Renderer-agnostic clip player: humanoid skeleton spec, keyframed clips, crossfading base/overlay layers, exercise state machine, and hysteresis rep counting. Zero dependencies; runs on any GPU or CPU.
- `apps/exercise-demo` - Web studio demo: procedural character playing squat/jumping-jack/curl clips with cheer + form-correction overlays, tempo control, optional BlazePose camera rep counting (CDN-loaded with simulated fallback), and SVG mascots reacting to the same event stream through the anatomy engine.
- `pipeline/` - Offline baking pipeline (Python): MotionDoc interchange format, RDP keyframe reduction + quantization, batch `bake-library` with manifest, positional retarget solver, ARDY `.npz` adapter. Baked JSON loads directly into the runtime via `clipFromMotionDoc` (the demo's "Squat · baked" button plays pipeline output). See `pipeline/README.md` for the full ARDY-on-Mac setup (gated Llama-3-8B token required once; generation is an overnight batch job, never device-side).

Run the demo:


## Codex Plugin

This repository is also a local Codex plugin. The plugin manifest lives at:

```text

```

The MCP command is declared in:

```text
.mcp.json
```

Build before using the plugin so `packages/mcp-server/dist/index.js` exists. The `.mcp.json` command uses `node` so it can resolve through the user's local environment.

```text
  rootPath: "examples/next-app",

  rootPath: "examples/next-app",

  svg: "<svg ...>",
  placement: { screenId: "<from app-context>", moment: "success confirmation" }
```
